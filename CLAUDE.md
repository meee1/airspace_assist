# CLAUDE.md — airspace_assist (Radio Calls AU)

Phone web app for Australian VFR pilots, especially helicopters. Target phone: Google Pixel 9 Pro (Chrome on Android); iPhones work too. It shows:
- the closest aerodrome (or the next one on the flight plan), with CTAF, ATIS/AWIS, tower and approach frequencies
- the aerodrome's runways (list plus a small to-scale diagram) and ERSA right-hand circuits
- a radio call guide that switches between CTAF and Class D procedures, with a runway picker and ERSA reporting points
- status tiles: GPS, TRK/HDG (compass auto-aligned to GPS track), PLAN (bearing and turn to the active waypoint), GS, ALT/AGL, CLASS (class here, cap, LL), and a second row with the CTAF of the aerodrome on screen and the AREA (or ATC) frequency at your position, each with the expected next frequency and its distance; a red NEXT CLASS row when class A/C/D or a restricted area starts within 10 NM ahead at your altitude
- the area frequency and the airspace stack for your position and altitude
- an airspace map at the top of the page (pan, pinch zoom, track/north up) with a 10 NM lead line, SRTM terrain, a CTAF layer, a VTC/VNC chart underlay, runways, VFR waypoints, navaids, towns and suburbs (CTAF, Terrain, Charts and Lead toggle)
- Go to with fuzzy search, phonetic-alphabet decoding, a mic button and a press-and-hold map menu, and GPX flight plans with auto-sequencing, an elevation profile, suggested VFR altitudes and a flight log
- all of it offline once loaded

Live at https://meee1.github.io/airspace_assist/app/ (GitHub Pages, from `master`, repo `meee1/airspace_assist`).

## Non-negotiable rules

1. **The AIP always comes first.** ERSA and the DAH are the primary source for every frequency, aerodrome and airspace limit. Other data is only a fallback where the AIP has nothing, and must be tagged with its source in the UI:
   - `VATPAC`: the vatSys dataset, which is a flight-sim dataset
   - `OurAirports`
   - `XC Australia`: unofficial, and only used if no DAH is loaded
2. **Never invent or "fix" a frequency, limit or procedure.**
   - If the AIP is ambiguous, show what it says and point the pilot to the ATIS, ERSA or NOTAM. Moorabbin's two tower frequencies are the example: they are labelled East/West only because ERSA's procedure text ties each to a side.
   - When sources disagree, show the AIP value and mention the other source as a note ("OurAirports says …").
3. **Safety wording stays.** Keep these in place and don't weaken them:
   - "Not an authoritative source"
   - the effective-date banner
   - the note that GPS altitude is geometric, not pressure altitude
   - the note that terrain is for awareness only
4. Copy is plain and direct, aimed at a pilot reading a phone in flight.

## Build (each AIRAC)

```
# inputs: data/aip/<ERSA>.pdf, data/aip/DAH_<date>.pdf, optional XC file,
# plus vatSys + OurAirports files in a data dir (see README "Refresh data each AIRAC")
cd tools
python3 build_data.py <datadir> data.json --ersa <ERSA.pdf|txt> --dah <DAH.pdf> --xc "<openair.txt>"
python3 - <<'P'   # add WMM variation grid (see README for the exact snippet)
...
P
python3 assemble.py && cp dist/* ../app/
```
- Needs `pip install pygeomag pillow pymupdf` and `pdftotext` (poppler).
- **UI-only change:** edit `tools/template.html`, re-run `assemble.py` against the existing `data.json`, then copy `dist/*` to `app/`. Don't edit `app/index.html` or `app/app.js` directly.
- `data.json` keys:
  - `ap`: aerodromes.
    - Source codes `cS`/`aS`/`wS`/`xS` are `E`=ERSA, `X`=XC, `V`=VATPAC, `O`=OurAirports. Conflicts are in `cf`.
    - ERSA extras: `st`/`utc` (state, UTC offset), `cnotes` (COMM notes incl. TWR HR), `proc` (procedure text), `keys` (CTR entry, circuit alt, reporting points, heli alt), `cct` (RH/LH circuits by runway end, with ERSA wording), `var`.
    - `x` tower entries may carry `[…, 'East'|'West', evidence]` from ERSA procedure text.
    - `rw`: `[end1, end2, lat1, lon1, lat2, lon2, lenM, surface, widthM, src, schematic]`. `src` is `DAH` (thresholds) or `ERSA`; schematic 1 = ERSA bearing, 2 = designator heading.
    - `t: 'H'` marks hospital/heliport sites by name; they're hidden unless "Show heliports" is on.
  - `asp`: airspace, as `[cls, name, lo, loKind, hi, hiKind, freq, poly, extra]`. Classes include `BA` (broadcast area), `FIA`, `EF` (class E frequency). `extra.u` lists ERSA controlling units; `extra.cc` is the CTR class.
  - `vw`: VFR waypoints `[code, name, lat, lon]` (ERSA).
  - `na`: navaids `[ident, type, name, lat, lon, freq]` (DAH + ERSA frequency).
  - `iw`: IFR waypoints `[name, lat, lon]` (DAH). Used for search/simulation only.
  - `sec`/`bnd`: vatSys sectors.
  - `meta`: ERSA/DAH dates.
  - `var`: WMM variation grid.
- Browser storage keys are all prefixed `rc_`:
  - `fp`: flight plan
  - `goto`
  - `mapRange`, `mapUp`, `mapCtaf`, `mapLead` (lead line, default on), `mapTer` (terrain shading on the map, default on), `mapCharts`, `chartOp`
  - `sim`, `simOn`, `simOpen`
  - `effOpen_<date>`
  - `cType`, `cSign`, `cCat`, `cMode`
  - `ahead`, `heli`, `all`, `theme`, `started`, `wake` (keep screen on)
  - `cmp`: compass alignment `{off, n, s, c}`
  - `tlog`: flight log (GPS fixes every 5 s for 6 h, plus waypoint-change events)

## Gotchas

- `fetch_srtm.py` arguments with negative numbers need `=`: `--around=-38.15,144.36,300`, `--bbox=-39.5,140.5,-33.5,150.5`.
- Line endings: `fetch_srtm.bat`, the XC `.txt` and `data/abs/UCL_2021_AUST_GDA2020.xml` show CRLF-only diffs from Linux/WSL shells. Don't commit those as changes; `git add` the files you changed by name.
- **Commit and push only when the owner says so.** Commit identity: `git -c user.name="Michael Oborne" -c user.email="mich146@hotmail.com" commit …` (the shell has none set), ending the message with the Co-Authored-By line. Push: the owner keeps a fine-grained PAT in the claude.ai project doc "GitHub pat". Read it with the Projects tool and push from the owner's computer shell with `git -c http.extraHeader="Authorization: Basic $(printf 'x-access-token:%s' "$T" | base64 -w0)" push origin master`, filtering the token out of any output. Never write it to git config, a file or a commit. The cloud session's own GitHub token has no access to this repo. The owner can also push from Windows (cmd, TortoiseGit). Check what's live with `git ls-remote origin master` and the `radio-au-<hash>` cache name in the served `sw.js`.
- After copying files into the repo from another environment, compare checksums (`md5sum`) with the build. A copy has silently left a stale `app/index.html` once, and the live site shipped without the change. `app/index.html`, `app/app.js`, `app/data.json`, `app/sw.js` and `tools/template.html` must come from the same build. The loader fetches `data.json?v=<hash>` and `app.js?v=<hash>`, so a mismatch shows up as stale data, not an error.
- Airservices, xcaustralia.org and the SRTM hosts may be unreachable from sandboxed shells. The owner downloads the PDFs and runs `fetch_srtm.bat` locally.
- `data/aip` holds Airservices copyright material (ERSA, DAH, VTC/VNC) in a public repo. Consider `.gitignore`-ing `data/`, since only the generated app is needed for Pages. Ask the owner before changing this.
- The app carries two AIRAC sets (see Two AIRAC data sets below). It shows a banner when the data isn't effective yet and warns when it's more than two cycles old.
- Tower-hours logic parses ERSA "TWR HR" notes, using local times and HDS by state. It doesn't know about public holidays or NOTAMs, and the UI says so.
- Outside tower hours, a Class D zone is shown as class G only where ERSA says it in one plain sentence ("Outside TWR HR airspace becomes Class G", `REV` in template.html). Avalon (becomes E) and zones whose wording has altitude limits or CTA conditions (Albury, Alice Springs, Gold Coast, Sunshine Coast, Broome, Tamworth, Hobart, Launceston, Canberra) stay as published. Don't widen this without reading each ERSA entry.
- ERSA entries without `ELEV` on the name line (water aerodromes, offshore helidecks) are found from the state/UTC/ICAO line. Without that, their COMM lines merge into the entry before.
- With a flight plan loaded, the aerodrome card follows the plan (`fpAerodrome`): the next plan aerodrome within 10 NM; that aerodrome within 15 NM when the active waypoint is one of its ERSA reporting points; then the last plan aerodrome within 5 NM; otherwise the closest. A pin still wins.
- The flight plan elevation profile (`profBuild`/`drawProf`) samples the plan about every 0.2 NM (500 samples max). It calls `terrainFt` and `airStack` at each sample and caches the result on a key: plan, tiles loaded, minute. Tile loads trigger `render()` and so a rebuild. Keep `airStack` cheap, because the profile multiplies its cost by about 500.
- The CTAF call location (`callName`) is normally the part after `/` in the ERSA name: MELBOURNE/MOORABBIN gives "Moorabbin", and BROOME/INTL falls back to "Broome". Where local usage differs, `CALL_AS` overrides it, with the source in a comment. The owner confirmed YBRS (BARWON HEADS/GEELONG) is called "Barwon Heads traffic". Add entries only from someone who flies there, not by guessing. Other slash names that may need checking: Kingscote/Kangaroo Island, Peterborough/Great Ocean Road, Ballina/Byron Gateway, Proserpine/Whitsunday Coast, Ayers Rock/Connellan.
- Airservices sells airspace as shapefiles (Shape Files, $5,950/yr) and CSV (Airspace Data, $1,950/yr) from data.airservicesaustralia.com, with no free download. The owner chose to stay on the free DAH PDF (Oct 2026). Don't add a shapefile path unless the owner provides the files.
- Offline: `assemble.py` writes the service worker. It precaches all terrain tiles at install into `radio-au-terrain`, which survives app updates. The app shell (index.html, app.js, data.json) is network-first with a 3 s timeout, falling back to the per-build cache `radio-au-<hash>`. Fonts go in `radio-au-fonts`. The footer `#offl` shows what's stored. Test with Playwright `context.setOffline(true)` after the SW is ready. The SW registers on https or localhost only.
- Traffic (TCAS-style): abandoned for now (27 Oct 2026); nothing is in the app.
  - **Display the owner picked:** TCAS symbols on the map (grey hollow diamond = other traffic, cyan filled = within 6 NM and ±1,200 ft, amber circle = within 2.5 NM and ±600 ft, relative altitude in hundreds of ft with a climb/descent arrow) plus an amber TRAFFIC row such as "2 o'clock 1.9 NM 300 ft above ↓", with a spoken callout.
  - **Why it stopped: the data source.**
    - api.adsb.lol `/v2/point/lat/lon/nm` works but sends no CORS header, so a page on github.io can't read it. It's also limited to 500 requests a day per IP.
    - Wi-Fi ADS-B boxes (GDL90 over UDP; Stratux uses ws://) can't be reached from an https page.
  - **Ways forward:** a Cloudflare Worker proxy (adds CORS and caches; still needs an adsb.lol key or a different feed), or a USB 1090 receiver over WebUSB on the Pixel (pingUSB, a CubePilot ADS-B board sending MAVLink ADSB_VEHICLE, or an RTL-SDR dongle).
- TAF decoder: abandoned (Oct 2026). The BOM TAF lookup (POST https://www.bom.gov.au/aviation/php/process.php, keyword=<ICAO>&type=search&page=TAF, returns HTML with TAF + METAR) sends no CORS headers, so it can't be fetched from meee1.github.io. aviationweather.gov was also blocked from the page. The options were a paste box with a BOM link, or a proxy (e.g. a Cloudflare Worker) hosted by the owner.

## Feature notes

- **Two AIRAC data sets.** `tools/data.json` is the current AIRAC and `tools/data-next.json` the next. `assemble.py` writes both, plus `urban.json`, to `app/`. The loader chooses by effective time: max(ERSA, DAH) date minus 8 h, i.e. 1600 UTC the day before (AIP GEN 3.1 4.3). In Oct 2026 the current set is ERSA 03 SEP 2026 with DAH 09 JUL 2026; the next is ERSA and DAH 26 NOV 2026. The DAH has its own cycle, so pair each ERSA with the DAH in force on the same date.
- **Urban areas.** `tools/urban.py` reads the ABS UCL 2021 shapefile (`data/abs/`, CC BY 4.0) via `pip install pyshp`, using `--urban data/abs/UCL_2021_AUST_GDA2020` in `build_data.py`. It keeps Major Urban, Other Urban and Bounded Locality, drops holes and simplifies to 0.0005°. The output is about 1.3 MB.
- **Suburbs.** `tools/suburbs.py` reads the ABS SAL 2021 shapefile (`data/abs/SAL_2021_AUST_GDA2020`, CC BY 4.0; git-ignored because the .shp is 143 MB, over GitHub's 100 MB limit) via `--sal` in `build_data.py`. Output: `sal` = [name, la x1e4, lo x1e4, state], one point per suburb at the centroid of its largest part, about 460 KB. `assemble.py` moves it into `urban.json` as `{urb, sal}`; the loader still accepts the old plain array. In the app, suburbs join `TOWNS` with `t:'S'`, and a suburb named like a town within 5 NM is dropped. Search gives them weight 0.5, skips letters-in-order matching (`lite`), and runs lev only when the first or second letter matches, which keeps a keystroke at about 15 ms on desktop with about 15k entries. Map labels appear at 5 NM range and below.
- **Altitude suggestions.** These are `legPlan()` in template.html, which uses the profile samples:
  - VFR levels from ENR 1.7 Table B, which applies at 3,000 ft AMSL or above (3.1.4).
  - Minimum height from CASR 91.265/91.267 and the MOS 12.01 note: 1,000 ft within 600 m over populous areas (300 m for rotorcraft), 500 ft within 300 m elsewhere. Terrain comes from the SRTM grid; there are no obstacles.
  - The ceiling is the class C/D/A base less `CTA_BUF` (user choice, default 500). Class E is not a ceiling.
  - Endpoint-aerodrome control zones are excluded.
  - `split` means no constant altitude works for the leg; `conflict` means some point needs more than the cap.
- **ERSA COMM parsing.** Section headings start in column 0. An indented all-caps line inside COMM is a wrapped service name (`DEP MELBOURNE` / `DEPARTURES`). Before this fix it ended the block and lost Essendon's TWR/SMC in the 03 SEP ERSA.
- **Chart underlay.** The owner chose to publish pre-rendered tiles (Oct 2026), even though the charts are Airservices copyright and the PDFs are marked copy:no.
  - **Built-in tiles:** `tools/chartiles.py OUT chart.pdf…` writes `app/charts/<sheet>-<edition>/<level>/<i>_<j>.jpg` plus `app/charts/index.json`, skipping tiles outside the panels. The page downloads them all by default (`chartsPrecache`, 4 at a time) into Cache Storage `radio-au-charts` and drops old-edition dirs. The service worker serves `/charts/*.jpg` cache-first from that cache.
  - **Imports:** users can still import a PDF on the phone. It is stored as `<sheet>-local`, listed in `charts/local.json`, and preferred over the built-in sheet.
  - **Rendering:** pdf.js 3.11.174 legacy build is vendored in `app/lib/pdfjs` and loaded only on import. It renders two levels (overview 0.5×; detail 2.5× VTC / 2.0× VNC) in 2048 px blocks, cut into 512 px JPEG tiles stored in Cache Storage `radio-au-charts` (`charts/<sheet>/<level>/<i>_<j>.jpg` plus `charts/index.json`). The service worker must keep that cache on activate.
  - **Calibration:** `tools/charts.json` holds the sheets: page size, name regex, levels, and panels each with a similarity and a clip polygon in PDF pt. `assemble.py` injects it at `/*__CHARTS__*/`.
  - **Model:** chart pt = similarity(LCC on a sphere, standard parallels 36S/39S, origin 37.8S 145E). JS `lccFwd` and `tools/chartref.py` must stay identical.
  - **New chart or edition:** run `tools/chartref.py` (label RANSAC, then a chamfer fit of the cyan C/D/A boundaries (fill 0,0.681,0.938) to the DAH). Expect a median misfit around 0.5 pt. Melbourne VTC: main 21.02 pt/NM (1:250k), Basin inset 35.02 pt/NM (1:150k). Melbourne VNC: 10.51 pt/NM (1:500k).
  - **Drawing:** `drawCharts()` maps three canvas corners to chart pt for an affine `ctx.transform`, clips to the panel polygon, and draws the overview tiles then the detail tiles.
- **Waypoint sequencing** (`fpAdvance`, like a GNSS navigator's fly-by):
  - within 0.5 NM of the active waypoint;
  - point 0 (departure): sequenced once you're more than 0.3 NM along leg 1 and within 3 NM of it;
  - past the turn bisector at the active waypoint, within 5 NM of it (on a straight leg that's simply abeam);
  - catch-up after a gap or a skipped point: if you're off the current leg, the first later leg you're within 2 NM of, part-way along, with your track within 60° of it;
  - a waypoint picked by hand (`FP.man`) arms once you're more than 1 NM from it and isn't skipped by the bisector or catch-up rules until you've closed 1 NM on it.
  Every change is logged in `tlog` (`fpLogEv`), and **Flight log** exports fixes and events as GPX for post-flight checks.
- **Real-flight check (27 Oct 2026, VH-EAN, Bell 206B, the example YBRS round trip).** Track from Flightradar24: open https://www.flightradar24.com/data/aircraft/vh-ean in the built-in browser and run `fetch('https://api.flightradar24.com/common/v1/flight-playback.json?flightId=<id>')` in the page (WebFetch and curl are blocked); about 2,800 fixes as `[ts, lat, lon, alt ft, kt, hdg]`. Replaying it through `fpAdvance`:
  - Before cc41743, sequencing stuck at YRSY for the rest of the flight: it needed "past it" and "within 3 NM" at once, and YRSY was passed 2.9 NM abeam.
  - Now all 13 points sequence: YRSY and WAN by the bisector (about 3 NM abeam), YTYA (skipped, flown along the coast about 7 NM away) by catch-up once on the YTYA→NAV1 leg, about 11 min later. Widening the bisector range to 8 NM would gain about 4 min there but risks early sequencing on sharp turns, so it was left at 5 NM.
- **Keep screen on** (`wakeAcquire`): the wish is `st.wakeWant` (`rc_wake`). The browser releases a wake lock whenever the page is hidden, so the lock is re-requested on `visibilitychange` and on any tap, and the button shows "Screen stays on" or "Screen on: tap to re-arm". Without the Wake Lock API (older iOS, Home Screen apps before iOS 18.4) a 16×16 silent looping H.264 video (data URI, about 1.5 KB) is played instead. Test with a fake `navigator.wakeLock` via `Object.defineProperty` in an init script; Chromium headless doesn't grant the real one.
- **Simulator inputs:** Alt, Track and GS apply on `input` (350 ms debounce), because a phone number pad has no Enter. When Fly is on with a flight plan, `flyStep` steers to the active waypoint unless `st.simManual` is set; typing a track while flying sets it, and pressing Fly again clears it. In sim mode `heading()` always uses the sim track, never the compass.
- **Top bar CTAF / AREA:** `#sCtaf` takes `ctafInfo(a).f` for the aerodrome on the card; `#sArea` takes the band at your altitude from `airStack` (label ATC and the class colour when it's C/D/CTR). Unit names are shortened (Ctr, App, Twr, Dep, Gnd). On screens 370 px and narrower the status grid is 3 columns and each of these takes a full row.
- **Search:** `searchPoints` (fuzzy: exact, prefix, no-space compact, word prefix, substring, Levenshtein ≤1/≤2, letters in order) over aerodromes, VFR waypoints, navaids, towns, suburbs and IFR waypoints, with type weights and a distance penalty of `min(15, NM/30)`. Per-string work (word split, compact form) is cached in `FZ`.
- **Compass alignment** (`cmpLearn`, `CMP`, button `#bCmp`): on each GPS fix with GS ≥ 20 kt, a compass reading under 2 s old, and track and compass both steady (change under about 3°/s plus 3° / 6° of jitter), the track − compass difference (true) goes into a circular mean: running mean for the first 30 samples, then a 30-sample EMA. After `CMP_MIN` (20) samples `heading()` adds `CMP.off` to the compass. It's saved in `rc_cmp`, reset by tapping the button, and not learnt in sim. It also absorbs the wind correction angle at the time of learning. Test by calling `onOri({webkitCompassHeading})` and `onPos({coords})` directly on a page loaded without `?sim`.
- **Next CTAF / AREA** (`nextFreqs`, `nxPath`, cache `NX`): path = rest of the flight plan from your position, else a great-circle line along track when GS > 5 kt, capped at 80 NM and sampled every 0.5 NM. CTAF: the first sample within 10 NM of an ERSA aerodrome (`s==='E'`, not `t==='H'`) other than the one on screen with a different `ctafInfo().f`. AREA: the first sample where the band at your current altitude (`airStack`, as in the stack) has a different `f`. Recomputed only when the key changes (position to 0.001°, altitude to 100 ft, plan index, track to 5°, CTAF and band), about 10–25 ms. The distance is placed before the name so a narrow tile truncates the name first.
- **Map gestures** (pointer handlers on `#map`, which has `touch-action:none`): one pointer pans (`MAP.pan`, north up), and a tap without movement picks a point. - **Android compass** (`tiltHeading`): `deviceorientationabsolute` gives Euler angles (W3C Z-X'-Y'', earth x East, y North, z up), and `360-alpha` is only right with the phone flat. Build R = Rz(α)Rx(β)Ry(γ). The screen-up vector is sin(so)·X + cos(so)·Y (so = screen orientation angle) and the back vector is −Z. Take whichever is more horizontal and use heading = atan2(vx, vy). Checks: flat α=90 → 270; upright β=90 α=30 → 330; landscape flat so=90 α=90 → 0. iOS keeps `webkitCompassHeading` + so (already tilt-compensated).
